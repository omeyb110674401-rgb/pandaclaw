## 2. 优先级规则（R2‴ 双轨）

1. **主轴=前置链**：每版先补齐「其他项的总前置」；前置链=安装可用性（B-A2）+ 真实证据（剧本库 S1）+ 议事规则底座（P9-1 等）。
2. **生态持续流（不落后）**：单人开发下生态是撬动复用的低成本杠杆——生态域不排队，随每个里程碑并行累积（知识资产组/轻量复用资产每版带一件）；**演示关卡主动创造复用信号**，不等待。
3. **信号门**：B-A1 预设终局等真实复用信号（1.9 演示关卡铺路后信号概率上升）。
4. **平台中介项**（工程底座 B-B 组）按前置性插队（如真实演练需要持久化时 B-B2 进入）。
5. **产品优先于生态的绝对排序取消**：生态可持续主导近版（如 1.9），产品深度作为里程碑主线轮替。

## 4. 里程碑完成定义（V1+V3 叠加）

每版「完成」须同时满足：

1. **V1 固定套件**：`pnpm run check` 全绿（typecheck + build + smoke 57 + client-render + review.unit）；
2. **V1 专项验证**：该版新增功能的专项验证（1.9=剧本库假体模式全绿；1.10=立案链场景绿；1.11=监督手段场景绿；1.12=参与/文书场景绿）；
3. **V3 场景剧本**：每版至少新增一本真实场景剧本（S1 剧本库，双模式：假体驱动进 CI + 真 LLM 驱动可切换）；
4. **主题四件套**：ADR（如需要）+ 实现 + 测试 + 文档/版本行。

## 5. 剧本库规范（S1）

- 位置：`tests/scenarios/`，每版新增一本（`scenario-<主题>.mjs`）；
- 双模式：环境变量 `PANDACLAW_SCENARIO_DRIVER=fake|llm`（缺省 fake，无 key 可跑、进 CI；llm 需 `DEEPSEEK_API_KEY`）；
- 剧本结构：目标会议类型 → 关键路径（建会→回路→表决→归档→复审→出口）→ 断言（终态/记录流/留痕）→ 演示文本（供教学卡/GIF 复用）；
- 剧本即验证门：每版完成定义 V3 要求新增剧本全绿。

## 6. 维护机制（M1）

- **每版启动**：从本文件「版本带/后置池」按 R2‴ 提项，确定该版主轴与顺手项；未列候选需论证入池；
- **每版收官**：完成项→存档区（版本历史），新增候选→对应组入池；本文件随版提交更新；
- **信号评估**：每次出现「他人复用/多插件共享域/复审大改」信号时评估 B-A1 是否提级。
