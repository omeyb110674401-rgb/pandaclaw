# ADR-0007：席位认证重绑制——断线恢复不破冒名防线

- 状态：已接受
- 日期：2026-08-26
- 关联调研：无直接制度卡（工程语义）；现实锚点＝人大代表资格审查委员会制度（代表资格变动经法定程序审查确认，非自动生效）
- 影响范围：`src/protocol.ts`（RecordKind+rebind）、`src/service.ts`（bindSeat 权威判定＋rebind 方法）、`src/tools.ts`（pc_rebind）、SKILL §6

## 背景

席位绑定（首用绑定会话、异会话同名即 NAME_TAKEN）是防冒名的好设计，但有一个死结：成员代理会中崩溃或团队重启后，重新派生的成员拿着同一个 persona 名字回来，会被**自己前世的绑定**永久挡在门外——应答率从此凑不够门槛，会议死锁只能作废。

## 决策

采用**主持人认证重绑制**（三案比较：维持现状＝一次断线即废会；票据制＝team 重启后 token 无处保存且工程复杂度不值）：

1. 新增 chair 专属工具 `pc_rebind(docId, name)`：主持人在**核实对方确系原成员**后调用；
2. 引擎写 `rebind` 锚点记录（含旧会话→新会话转移的审计文本），此后该名字的绑定权威转移至新会话；
3. **旧会话随即失效**——同名提交被拒，防止「崩溃恢复」变成「冒名后门」；
4. 重绑仅限断线恢复场景，不得用于中途换人。

绑定权威判定规则：最近一条 rebind 记录优先；否则归属首个实体产物的会话（与原行为完全兼容）。

## 后果

- 正向：一次断线不再废会；防线保持对称（重绑后旧会话同样被拦）；全程留痕可审计。
- 代价：主持人多一步核实义务；引擎新增一个 RecordKind 与一个主席台工具。
