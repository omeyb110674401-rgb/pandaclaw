# ADR-0002：MIN 确认阶段采用「确证书」语义——记载性文种不做票决

- 状态：已接受
- 日期：2026-08-26
- 关联调研：docs/research/C-公文体系.md L296-L323（条例定义＋异议窗口条款）、C-补-P05（纪要免章·记载性生效）

## 背景

插件实现把 MIN 的确认阶段当成了正式表决：`VOTE_STAGES.MIN=['confirm']` 强制完整前置门（须有已收录意见书＋书面质询）＋机械计票。这与协议正文 §5「归纳总结宣布，成员 ≤60 字确认或更正，无异议即过」直接冲突；演练一全绿恰恰因为跑的是重路径，掩盖了矛盾。

调研还原了纪要的制度内核：

1. 条例第八条：纪要「适用于**记载**会议主要情况和议定事项」——记载性文种，动词是「记」不是「决」；议定在先，纪要在后，纪要不产生决定。
2. 效力形态佐证：凭红色标志生效、免印章、无成文日期要素（C-补-P05）——唯一的「记载性生效」文种。
3. 异议窗口条款：「与会单位对议定事项有异议的，应在参会期间或会签期间明确提出，**事后不得拒绝落实会议精神**」——确认程序的内核是**真实性核验窗口**：成员被问的是「记录是否如实」，不是「是否批准决定」。

## 考察过的方案

| 方案 | 内容 | 裁决 |
|---|---|---|
| A 去表决化 | confirm 改直办，关闭成员通道 | 否：丢失成员确认权这条民主底线 |
| B 确认制表决 | 保留赞成/反对/弃权，「无人反对即过」 | 否：换了形式的表决机器，仍问「你是否批准」——形式变了，内核没变 |
| C 双轨配置 | validation 决定轻重 | 否：为想象需求加复杂度 |
| **D 确证书（采纳）** | 成员输出 `确认 / 更正：<失真处>` | ✅ 忠实于核验语义 |

## 决策

MIN 确认阶段的机器强制点取内核三件：

1. **确证机会强制**：confirm 保留为必经阶段，归档前必须有全员确证窗口；
2. **异议落痕强制**：pc_vote 在 MIN 类型下语义切换为确证书——stance 枚举 `['确认','更正']`，更正内容写入理由并留痕；
3. **更正处理强制＋防死循环**：出现更正 → 主持人必须修订记录并重新发起确证；循环上限 ≤3（语义为纠错上限，非三审制）。

同步豁免与收紧：

- **豁免**：质询前置门（核验不是质询）；计票公式（核验不是票决——机械规则仅为「无更正且应答率达标即确证」）。
- **收紧**：应答率不足时**阻止归档**（不同于 CON 的降级征询——MIN 的全部价值就在确证，确证不完整则一无所有）。

## 后果

- ✅ MIN 回归「便宜的确证通道」定位：轻量场景不再被迫走重回路。
- ✅ 协议正文 §5 与机器行为首次完全一致（§5 本来就写对了，是实现错译）。
- ⚠️ pc_vote 成为**类型驱动语义**的工具（MIN=确证书 / 其余=选票）：成员视角工具面统一，但实现与文档必须显式标注双语义。
- ⚠️ 协议须出 v2.5 修订（§5 补确认制机械定义＋MIN 打回语义改为更正处理）。
