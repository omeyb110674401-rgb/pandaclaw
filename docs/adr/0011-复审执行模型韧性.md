# ADR-0011：复审执行模型韧性——泵/替身生命周期的失败与恢复

- 状态：已接受
- 日期：2026-08-27
- 关联：ADR-0010（复审回告闭环与执行模型细化）、ADR-0008（本地时钟，无墙钟等待）
- 影响范围：`src/protocol.ts`（RecordKind +review-event）、`src/service.ts`（CAS 推进/启动扫描/重建/dispose 兜底/restart/生命周期/review-event 落板/归档门禁 tally 检查）、`src/index.ts`（spawner 返回可 dispose handle、dispose 监听、启动扫描钩子）、`src/tools.ts`（pc_review action=restart）、`src/client/MeetingStage.tsx`、测试、SKILL

## 背景

ADR-0010 定下「归档位点批量泵」自动出审的语义，但执行层的失败路径未定义：泵只在归档位点触发（重启后 filed 档案无人泵）、审查替身 spawn 是 fire-and-forget（失败不可见、状态却已到 reviewing——「幽灵审卷」）、替身交卷前死亡（进程崩溃/会话被杀）无恢复通道、多入口可并发重复出审同一档案。本 ADR 把执行模型失败路径全部显式化，与既有哲学同构：自动的归自动、真人的归真人、记录流唯一真相、无墙钟、配置错误 fails loud。

## 决策（Q1–Q12）

### 1. 泵启动恢复：服务启动扫描一次（Q1-A）

服务装配完成后延迟一拍（`setImmediate`）执行 `pumpMainReview()`：扫描待审池全部 `filed` 主力档（RES/LEG）按 priority 排序串行出审。进程启动是事件，不设墙钟。重启后滞留的 filed 档案自动续审（ADR-0010 Q3-B 的归档位点泵之前，启动扫描是唯一补位入口）。

### 2. spawn 失败：await 真串行＋回滚留池（Q2-2A）

`startReview` 改为 `await` spawn 再推进：spawn 成功才 `advance('reviewing')`；失败回滚 `filed` 留池（泵继续下一个档案，单档失败不阻塞整池）。泵的「串行」从注释谎言变为事实（前一个 spawn 完成才下一个）。`filed = 待出审` 的池语义保持唯一真相。

### 3. 替身交卷前死亡：启动重建（Q3-3A）

进程重启后，停 `reviewing`/`accepted` 的档案以记录流为准重建：已有「审查主体」意见记录（掉在落板与状态推进之间）→ 按意见推进（有异议方→hearing，无→decidable）；无审查意见 → 回滚 `filed` 重新泵。记录流唯一真相、状态是投影——投影永远可从记录重建。

### 4. 并发重复出审：条件推进 CAS（Q4-4B）

`advanceReview` 派生 `advanceReviewIf(docId, predicate, mutate)`：predicate 在域存储的原子读改写回调内检查当前状态；`startReview` 用「当前 state === 'filed'」作谓词，不满足返回 false 不 spawn。幂等性从「先读后写」升级为「原子条件写」，未来新入口天然免疫。

### 5. 运行中替身不交卷：事件兜底＋逃生门（Q5-5B/5C）

- **5B dispose 事件兜底（自动）**：监听 `agent/disposed`；审查替身会话（sessionId 前缀 `subagent-review-`）被 dispose 且档案仍在 `reviewing`/`accepted` 且记录流无审查意见 → 回滚 `filed` 自动重泵。被外力杀死是机械可判的，无需用户介入。
- **5C 逃生门（真人）**：`pc_review` 新增 `action=restart`：主持人（用户授意）把 `reviewing`/`accepted` 档案回滚重审。不可机械判的卡死（替身活着但不交）由用户兜底。

### 6. restart 语义：立即重开审查（Q6-A）

`restart` = 回滚 `filed` 后当场同步走完一次 `startReview`（filed→accepted→spawn→reviewing 一串完成），不等泵（回滚留池无人泵——主力档启动扫描已过、弱档不入池）。适用状态仅 `reviewing`/`accepted`（hearing 走 close-hearing、decidable 直接 adjudicate、feedback 直接 reply——各有其道）。旧替身若还活着可能继续交卷——被 CAS 状态门拒绝，无害。

### 7. 恢复动作留痕：review-event 系统事件（Q7-A）

所有恢复/失败动作落板为系统事件记录（新 `kind='review-event'`，`authorName='系统'`，stage='review'）：spawn 失败回滚、dispose 回滚、restart、启动重建推进/回滚各留一条（含原因/触发点）。记录流完整呈现审查轨迹，审计口径与重建逻辑一致——「记录流唯一真相」不因恢复路径而破例。

### 8. 失败可见性分层（Q8-A）

- 自动语境（泵/启动扫描/dispose 兜底）：失败回滚 + review-event 留痕，不抛错、继续下一个；
- 用户语境（dispatch/request/restart）：失败抛错给发起人（明确「出审失败：替身未能创建，已回滚待审池，请检查底座后重试」）+ 回滚 + review-event。失败反馈只给发起的人。

### 9. 恢复路径全档位（Q9-A）

启动重建与 dispose 兜底覆盖**所有档位**已进入审查流程的档案（弱/次级档 dispatch 后的替身同样会死）；泵保持主力档。恢复是无差别义务（替身死了都要救），自动出审才是档位特权。启动扫描内部顺序：先重建（全档位 reviewing/accepted），再泵主力档 filed（含刚回滚出的）——一次扫描闭环。

### 10. 替身生命周期显式化＋清理死会话（Q10-A/C）

- **A 运行中**：`spawnReviewer` 保留 handle；交卷（reviewVerdict 成功）、回滚（spawn 失败）、废弃（restart）时主动 `dispose()`（底座 `SubagentRun.dispose()` 幂等、释放资源）。替身 = spawn → 工作 → dispose，无常驻；
- **C 启动时**：启动扫描清理 `subagent-review-*` / `subagent-supervisor-*` 死会话（进程重启后它们必然无驱动者，dispose 安全；插件热重载不触发进程启动扫描，无误杀面）。

### 11. 扫描时机与全员失败 loud（Q11-A）

启动扫描在插件装配完成后延迟一拍（`setImmediate`，让 agents/preset 就绪）；扫描结束若池非空且无一出审成功 → 落一条 review-event 并输出 loud 错误日志（「待审池全员出审失败：检查 pc-reviewer preset 装配」）——配置错误显式暴露，临时故障仍走 Q8 静默回滚。

### 12. 监督替身纳入同一韧性框架（Q12-A）

监督替身（ADR-0010 §9）复用本 ADR 的 Q2/Q7/Q8/Q10：await 串行、失败静默回滚（tally 门二受阻语境无人听）+ review-event 留痕、生命周期 dispose、启动清理 `subagent-supervisor-*` 死会话。**唯一差异：无 restart**——监督窗口的「出口」是 tally 重试（门二事件驱动重试本身＝恢复机制），用户在场可直接 `pc_record kind=supervision` 代录（既有兜底）。

## 后果

- 正向：执行模型从「事件触发的一次性泵」升级为「自愈系统」——重启恢复、替身死亡恢复、并发免疫、失败可见、轨迹可审计；恢复机制全部事件驱动（无墙钟）；「自动的归自动 / 真人的归真人」落地为机制事实。
- 代价：`startReview` 从线性推进变 CAS+await+回滚（复杂度上升）；新 kind `review-event`；spawner 接口从 `Promise<void>` 升级为可 dispose handle；启动扫描/重建/dispose 监听新增三条系统路径；归档门禁新增 tally 检查（Q17-A，见 ADR-0010 效力语义修正）。
- 与 ADR-0010 的关系：Q1–Q12 全部是执行层语义，不改变 ADR-0010 的协议层（六阶段状态机/分层/降级标记/专项出口）；效力处置的修正（修订谱系/解释同义务/三分类收敛）见 ADR-0010 追加小节。

## 后续

- 启动扫描对 `decidable`/`feedback` 保持原状（悬置等用户，不设墙钟）；`hearing` 保持原状（异议方续接既有语义）。
- 死会话清理依赖底座 `ctx.agents.list()` 的可枚举性；若底座无 list，C 部分降级为「只清运行中」（A 仍有效）。
