# ADR-0006：监督窗口——用户作为民众监督者的介入通道

- 状态：已接受
- 日期：2026-08-26
- 关联调研：A-补-P20《立法公开征求意见的时限与反馈义务》、B-补-P19《社情民意与公众意见入口》、D-补-P112《公开建言的意见量级与反馈闭环》（三线并行取证）
- 影响范围：`pandaclaw-meeting/SKILL.md` §4 监督窗口节、`CONTEXT.md`

## 背景

Q4-A/B 裁定后用户角色仍剩一维：用户可否以民众监督者身份在会中提出监督与质疑？用户以「一般条例都有公示期」为由提案。风险点：外部输入若处置不当，或冲击「决定必经表决」边界，或在计票中制造程序混乱。

## 调研依据（三卡合成）

1. **窗口时机有法条级锚点**：立法法 §40（2023）——列入常委会议程的法律案「应当」向社会公布征求意见（唯一例外＝委员长会议决定不公布），时间「一般不少于三十日」，且窗口开在「**常务委员会会议后**」（审议轮次之间）；实务两批窗口均整 30 日（A-补-P20）。行政法规/规章层：制定程序条例 §13/§15 同为应当＋30 日，§19③ 未按规定征意可**缓办退回**（硬门禁）（D-补-P112）。
2. **反馈义务法定为两级制**：①全量收集整理分送（§41）；②征求情况向社会通报（§40 第 3 款）。逐条答复提意见人现实无明文——实务形态是法工委记者会点名通报采纳情况、广州邀请线索提供者参加督办；而**会后**备案审查语境下向建议人反馈有明文（立法法 §113，D-补-P112）。两个窗口两种义务，不矛盾。
3. **外部意见无动议资格有一手原句**：深圳征集公告「本次征集的只是提案线索而不是政协提案」（B-补-P19）；政协章程第十一条将社情民意信息列为正式文书形式，流转＝委员反映→专门机构→内刊上报。
4. **入口纪律**：基层立法联系点核心纪律为「**原汁原味**送达、不加工不过滤」（临洮 259 部草案/3299 条/采纳 627 条；虹桥十年 4525 条/361 条采纳）。
5. **量级参照**：十五五网建 311.3 万条→梳理摘编 27 方面 1500 余条→体现进《建议》的三级漏斗；政府工作报告网建通道属政策性安排非法定程序；白皮书无公众征意（证据缺失型结论如实留空）（D-补-P112）。

## 决策

1. **两顶帽子框架**：会中（⭐阶段进行时）用户＝民众监督者（实质输入经协商回路）；门上（验收门/征询呈报处）用户＝程序裁量者（仅三选，ADR-0004/0005）。
2. **窗口时机**：任意 ⭐ 阶段受理监督质疑（各征意阶段为主窗），**计票启动即关窗**（同构「常委会会议后开启、表决前关闭」）；归档后的质疑走复审子通道触发（同构备案审查公民建议，§113 反馈义务随之适用）。
3. **入板方式与纪律**：主持人**代录** `opinion-{案卷号}-{stageid}-用户`（或 inquiry），标注「代录·用户」；**原汁原味不改写原文**；照过 M4 准入但不因批评性被拒；**不替代成员产物的前置门计数**；STR 终审阶段的用户输入加标「参考输入·非表决性」。
4. **效力边界**：监督意见＝输入非裁决（「线索≠提案」锚点）——经质询答复、《意见处置清单》逐条处置、必要时打回重议、表决落文；用户不因此获得投票权。
5. **反馈义务分层**：
   - 法定同构（基础档义务）：全量收集整理进审议资料流＋征求情况向全员汇总通报（§41/§40③ 同构）；
   - 协议强化语义（须标注）：《处置清单》逐条回告用户——现实中仅为记者会点名/邀请督办的实务形态；
   - 会后复审：review-request 提出人依 §113 同构享有反馈。
6. **引擎零改动**：全部由既有原语（pc_submit 代录路径、chairRecord 处置清单、复审子通道）承载。

## 后果

- 用户权力画像完整化且项项有制度对应：召集权＋程序否决权（门上三选）＋监督输入权（窗内）＋复审触发权（会后），无一项绕过表决。
- 与既有机制天然衔接：代录复用 headless 惯例；《处置清单》复用 R3 双联交付。
- 代价：主持人多一层代录与转写纪律约束；STR 终审对用户输入从严标注。
