# ADR-0004：征询模式效力边界与呈报三选制

- 状态：已接受
- 日期：2026-08-26
- 关联调研：docs/research/A-补-P05《法定人数效力边界》（两部议事规则全文穷尽核验）
- 影响范围：`src/tools.ts`（pc_tally 描述与渲染）、`pandaclaw-meeting/SKILL.md` §4 启动门槛与失败分支、tests/smoke.mjs

## 背景

R4 启动门槛条款规定应答率不足时「降级为征询模式（结果仅供参考、标注未达法定状态）」，但未定义该产物的效力与出口。实现侧将 consultive 计票照常按公式计算 passed 并汇入普通失败路径（打回重议），产生三处矛盾：

1. 「仅供参考」被实现为「自动否决」——名不符实，且白白消耗三审制轮次；
2. 调研认可的原初自创语义是「不足即**不进入表决**并降级输出」，而给未达应答率的票判 passed/fail 恰把它当成一场失败的表决；
3. 若反向放任照常归档，文件携带的票数未达任何法定门槛，「决议」名不符实。

## 调研依据（A-补-P05 结论）

- 两部议事规则无任何「中止／延期审议／另行召集」事后救济明文；现实内核＝**门槛绝对性**：不足即不开会，无任何产出物；
- 「降级征询」为**协议自创工程语义**（现实无此明文），因与「硬前置」结构同构而获认可，但须维持「协议自定」标注纪律；
- 中断/不足的具体处置语义属**协议自主设计空间**，须自洽填充；
- 薄锚点旁证：立法法 §45 单个法律案搁置由委员长会议**决定**延期审议——门槛失守后的处置指向主持机关裁量而非状态机自动行为。

## 决策

1. **征询产物不构成表决**：consultive 计票不得作为通过/不通过的表决结论使用；
2. **出口唯一经用户裁量（呈报三选制）**，全部验收档（含 skip/key）在此强制请示：
   - ①采信：登记 resolution 并强制标注「征询采信·未达法定状态」，走完阶段收尾后归档；
   - ②再议：提炼缺席与分歧要点为焦点，回 ⭐ 阶段重议一轮（正常消耗轮次）；
   - ③终止：搁置终止归档（附原因）。
3. **引擎零门禁**：三条出口全部由既有原语表达，引擎不为征询模式增加状态或校验；语义由工具渲染提示与本协议承载。

## 后果

- 正向：抢救部分完成的协商工作而不虚构法定性；把「机器无法收敛」显式转化为人类决策输入；打回重议保留给实质性异议。
- 代价：主持人多一次请示回合；采信决议的「非法定」标注随文存档（审计链可见）。
- 与 MIN 的不对称是刻意的（ADR-0002）：MIN 的全部价值在确证，应答率不足阻止归档；其余类型的协商产物有独立参考价值，允许降格存续。
