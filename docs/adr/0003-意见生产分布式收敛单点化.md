# ADR-0003：意见生产分布式、收敛单点化——STR 内圈改三形态裁定，终审采一致同意

- 状态：已接受
- 日期：2026-08-26
- 关联调研：docs/research/B-补-P11（政协专题议政性常委会全流程）、D-补-P113＋D-补-P17（党内审批链递进审议）、A-补-P03（人大常委会议事规则第三十一/四十五/四十八条）

## 背景

v2.0 实现 `VOTE_STAGES.STR=['inner-review','final-approval']`——同一批 npc 投两轮票。交叉核验三条轨道的原始调研后发现这是全矩阵唯一的「双收敛」违例：

| 轨道 | 审议形态 | 收敛时刻 |
|---|---|---|
| 政协专题议政性常委会 | 分组/界别讨论贯穿会期，只产共识意见 | 闭幕会一次表决（A 级一手通稿） |
| 人大常委会 | 分组审议只产审议意见；委员长会议决定付表决 | 全体会议表决（第三十一/四十五/四十八条） |
| 党内审批链 | 领导小组→国常会→政治局常委会逐级审议，输出恒为「原则同意／修改意见／一致同意」，无任何票数记录 | 常委会「一致同意确定为一号文件」（合议一致） |

另：「政治局**全体会议**审议一号文件送审稿」的句式在任何年份均检索不到——STR 终审的现实锚点是常委会合议而非全体票决。

## 决策

### 一般原理（入典）

> **意见生产是分布式的，意见收敛是单点的。** 一个案卷的完整回路中，表决/裁定动作只发生一次（收敛点），其余环节全部是意见生产。收敛点的形式依被模拟机构的现实惯例选择：计票过半数／重大事项 2/3／合议三形态／确证书。

据此六类矩阵的计票配置全部获得制度出处：CON/RES deliberation＝政协闭幕会与机关会议决定（过半数）；PLA approval＝全国人大表决规划纲要；LEG publish＝法律案表决；MIN confirm＝确证书（ADR-0002）；**STR 是唯一违例，本 ADR 修正之**。

### STR 具体修正

1. `VOTE_STAGES.STR` 收窄为 `['final-approval']`；
2. inner-review 保持 ⭐回路（成员意见书/质询＝分组讨论与汇报审议的映射），主持人产出**三形态裁定**（原则通过／退回修改附意见清单／暂不讨论），以新锚点种类 `ruling` 登记并附双联交付的意见处置清单；推进出 inner-review 前强制校验 ruling 锚点存在；
3. 「退回修改」回 drafting 并消耗一轮；「暂不讨论」由主持人以搁置终止落地（pc_adjourn terminate）；
4. **final-approval 通过线采「一致同意」**：`赞成 === npc编制`（经应答率前置门后全员赞成）——忠实于党内链「一致同意」的合议一致内核。

## 落选方案与已知代价

- **内圈保留计票**：把递进审议误译为两次收敛，无制度出处。
- **终审沿用 ≥2/3**（审查者曾以此为由推荐机制化近似）：被否——用户裁定现实一致性优先。
- **已知代价（接受）**：一致同意对 LLM 成员的随机 dissent 脆弱——单个反对即阻断终审。缓解：失败走焦点提炼→终审阶段内重新审议（`pc_stage round`），≤3 轮防死循环；耗尽即搁置终止。这与现实同构：未获一致同意的文件当年即不被列为一号文件，经再酝酿后另行上会。
