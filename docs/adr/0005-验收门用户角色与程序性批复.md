# ADR-0005：验收门用户角色——程序性批复三选制

- 状态：已接受
- 日期：2026-08-26
- 关联调研：docs/research/D-补-P17《一号文件党内审议层级证据链》、D-补-P16（起草组构成）
- 影响范围：`pandaclaw-meeting/SKILL.md` §4 验收门＋红线4、`CONTEXT.md`

## 背景

full/key 验收档要求 R4 后暂停请示用户，但协议未定义用户此刻的角色：用户回复的实质意见（如「把第 3 条改了再过」）算什么？候选：编外合议人（回复直写决议）／上级机关（批复即文书）／程序性裁决者。

## 调研依据

党内审批链（D-补-P17）的现实形态：领导小组→国常会→政治局常委会逐级审议，各级输出恒为「原则同意／修改意见／一致同意」类**程序性意见**，由起草方落实后再进入下一环节——审批意见从不跳过审议直接成文。且核心边界条款「协商者无决定权、决定必经表决」（§4 红线）若可被用户批复绕过，验收门即成后门。

## 决策

1. 用户在验收门只裁**程序三选**：
   - ①放行——登记 resolution 后走收尾归档；
   - ②附意见打回——用户实质意见由主持人转写为焦点（`issue-{案卷号}-{stageid}-focus`）回 R1 重议（正常消耗轮次）；
   - ③终止——搁置终止附原因。
2. 用户实质修改意见**不得直写进决议文本**，一律经协商回路落实后表决；批复不构成票、不改变通过规则。
3. **引擎零门禁**：验收门暂停本身是行为规约（主持人主动请示），三选出口全部由既有原语承载。

## 后果

- 正向：守住「决定必经表决」边界；用户的程序否决权实际强于任何一票，裁量权无损。
- 与 ADR-0004 同源的一般原理成型：**人类裁量只产生程序性处置，实质内容必经协商回路与表决**。
- 代价：用户想直接拍板时须接受一轮回路延迟；主持人增加一次转写义务（批复→焦点）。
