# ADR-0009：用户缺席替身监督——监督窗口两阶段模型

- 状态：已接受
- 日期：2026-08-26
- 关联调研：ADR-0008（关窗预告）同链；ADR-0006（监督窗口）；现实锚点：公益诉讼／支持起诉的**代表人机制**——缺席公众由代表主体代为发声，其意见可溯源、可被当事人追认或撤回
- 影响范围：`src/protocol.ts`（RecordKind+supervision）、`src/service.ts`（superviseStandin+tally 门二）、`src/tools.ts`（pc_supervise 监督面）、`src/index.ts`（替身装配面）、`src/client/MeetingStage.tsx`（二阶段徽章）、测试、SKILL

## 背景

ADR-0008 把监督窗口的门禁做成机械强制，但留下一个问题：用户（唯一的真人监督者）**不可能 24 小时守在会话前**。窗口开着时他不在；他在时流程已在走。会中实时监督对单人用户结构性不可达。

把监督兑现全押在「会中、⭐、实时」这个面上，等于默许用户全天候在场——LLM 会话形态下是错的。需要一条**异步兜底**：用户缺席（未作任何回应输入）时，由一个以用户监督立场为职责的替身代为发声，且其发言**不算票、可被用户追认或撤回**，不越俎代庖、不留假手。

## 决策

监督窗口改为**两阶段模型**，第二阶段由替身兜底：

1. **一阶段·本人窗**：⭐ 阶段进行中，用户本人可提监督意见（权威通道）。
2. **二阶段·替身窗**：⭐ 阶段计票位点到达（warning 已预告）而用户全程无任何回应（无 `supervision` 记录）时，由 **用户监督替身** 代为提出监督意见，**作用于当轮**（进摘要/焦点提炼、参与当轮收束），不滚到下一轮、不押归档复审。
3. **替身身份**：经底座以专用 preset `pc-supervisor-standin` 创建的子代理；插件按其 `agentPreset` 装配**监督面**（`pc_supervise`），不进入成员面（成员面会装 vote/submit——替身不是投票成员）。
4. **替身发言纪律**：登记 `supervision` 记录（标注「代·替身」），**不算票**、不替代成员产物前置门计数、不改变通过规则；只提监督质疑（风险/遗漏/程序关切），禁止代用户表态。
5. **效力与可撤回**：替身意见入审计链；用户回来自动获得**追认/撤回权**——对替身意见的回应消息即为撤销依据。`supervision` 记录同源两种形态：`代录·用户`（主持人代录本人意见或明示放弃）与 `代·替身`。
6. **仲裁位**：门二（ADR-0008）只检查 `supervision` 记录存在性；「意见／放弃／替身」三种收束方式由主持人依用户在场情况裁量——机器强制存在，故事决定内容（与 RULING 门同构）。

## 后果

- 正向：监督从「必须实时在场」变为「缺席也有代言」；用户回来可推翻替身意见，防线不破；`pc_supervise` 与成员工具面严格分离，替身永远不碰选票。
- 代价：一个 RecordKind、一个新工具、一个专用 preset 约定；主持人多一条「用户缺席时 spawn 替身」的义务（由门禁困住强制）。

## 后续

复审子通道（归档后异步监督、反馈义务两级制的逐条回告）在本裁定中定为另一条独立通道（ADR-0006 已有语义），UI 以「复审判子通道·异步监督」入口先行呈现，数据面待真实需求落地。
