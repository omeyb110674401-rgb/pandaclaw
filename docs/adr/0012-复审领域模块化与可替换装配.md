# ADR-0012：复审领域模块化与可替换装配（PandaClawStore/ReviewService/AgentHost）

- 状态：已接受
- 日期：2026-08-27
- 关联：ADR-0010（复审回告闭环）、ADR-0011（复审执行模型韧性）；grilling 拷问裁定链 Q1–Q27（详见 `docs/复审模块化与可替换架构工作文档.md` 裁定链总表）
- 影响范围：`src/store.ts`（新，领域仓库）、`src/review.ts`（新，复审领域类）、`src/host.ts`（新，AgentHost 抽象）、`src/service.ts`（瘦身：会议核心 + 壳转发）、`src/review-tools.ts`（新，复审工具面）、`src/client/review-panel.tsx`（新，复审面板）、`src/index.ts`（装配：makeAgentHost + 注册四组装备策略）、`src/domain.ts`（行类型别名）、`src/protocol.ts`（MAX_TEXT_CHARS 归位）、`tests/review.unit.mjs`（新）、README、SKILL

## 背景

ADR-0010/0011 落地后，复审闭环（18 公开方法 + 8 私有辅助 ≈ 540 行）与会议核心（convene/stage/tally/adjourn 等 9 方法）混居 `service.ts` 单文件单体（1386 行）。病灶：①复审与会议核心耦合在类内部（改动互相牵制）；②对 dsh 底座（agents/tools/team）的依赖散落在 index.ts 的 spawner 字面量与 equipSessions 闭包里，未收敛为可替换的契约面；③工具面/客户端面板与业务层同文件，边界靠纪律而非结构。经 grilling Q1–Q27 拷问，确立本轮 A 阶段三目标：模块化（复审解耦为独立领域类）、依赖可替换（底座依赖收敛到 AgentHost 契约）、为 B′（一键预设终局）铺路。

## 决策（Q1–Q27 摘要）

### 模块化拆分（Q1–Q15）

- **Q1-A**：先单插件模块化（A），终局演进为插件包＋一键 preset（B′，见「后续」）。
- **Q2-2A**：复审 18 方法全量抽取进 `ReviewService`（领域类）；会议核心反向依赖只剩两个单点（adjourn 调 `pumpMainReview`/`reviewFlagOf`，Q8-A）。
- **Q3-A/Q4-B/Q5-A**：`PandaClawStore` 独立领域仓库（贫血门面：纯数据访问与机械数据整形，业务推导留富领域类）；会议核心与复审都走 store；store 粒度＝Q5 清单（meeting/putMeeting/updateMeeting/allMeetings/records/putRecord/nextSeq/tallies/putTally/advanceReview/advanceReviewIf/recordReviewEvent）。`allMeetings` 为接口必要补全（泵扫描/文号编号/恢复扫描需要）。
- **Q6-A**：平铺文件组织：`store.ts`/`review.ts`/`service.ts`/`review-tools.ts`/`host.ts`；共享类型原位（protocol/contract/errors/fold/domain 不挪；行类型别名归位 domain.ts，MAX_TEXT_CHARS 归位 protocol.ts）。
- **Q7-A**：`service.ts` 保留 12 个同名壳转发（签名原文照抄、一行转发）+ `get review` 属性直连——外部（工具层/smoke）零改动，签名不变即行为不变证明。
- **Q9-A/Q10-A**：`review-tools.ts` 与 `client/review-panel.tsx` 纯搬家（逻辑零改动）；面板搬运同时下沉重用原语（palette/chip/Copier，单向依赖无循环）。
- **Q11-A**：smoke 57 组零改动当回归护栏 + 新增 `tests/review.unit.mjs` 独立单测（fake store/host 直测边界，9 组 11 断言）。
- **Q13/Q20 合并**：`ReviewService(store, host)`；supervisorSpawner 职责并入 host。
- **Q15**：ADR-0012 落档 + 插件 1.8.0；协议 v2.13 不动（模块化不改变协议语义）。

### 依赖可替换（Q17–Q23）

- **Q17/Q18-A**：契约显式化三面——组合层换行（cordis.yml 天然支持）、`AgentHost` 抽象、依赖契约文档（本 ADR「对宿主要求」清单）。
- **Q19–Q21**：`AgentHost` 接口收「装备工具（equip/registerEquip）＋创建替身（createStandin）＋枚举会话（listStandins）＋统一清理（dispose）」；`makeAgentHost(ctx)` 装配层函数实现（自带 dispose）。
- **Q22-A**：装备机制进 host（agent/created 分发 + tools.register + 现存会话补装），装备策略留 index.ts（`registerEquip` 四组：主持人/监督替身/审查替身/成员面）。
- **Q23-A**：`host.dispose()` 统一清理（销毁全部替身 + 撤全部装备注册 + 移除监听 + 清启动定时器）。

### 终局形态（B′，Q14/Q16′/Q24–Q26，本轮只记设计不实现）

见「后续」章节。

## 后果

- 正向：复审与会议核心的边界成为代码事实（不是纪律）；底座依赖收敛为一个接口（替换实现＝换 AgentHost，业务零改动）；工具面/客户端面板按域归位；单测可直测复审边界（快迭代不经过会议流程）；B′ 的工厂导出/双层部署已有现成锚点。
- 代价：`service.ts` 的 12 个壳转发是间接层（一行转发，成本低）；store 是第三个数据通道（原 domain 直连 + 两个领域类）；`standinSpawnerHost` 兼容适配器需随 B′ 消亡；`ToolFactory` 与 `service.ts` 类型互为 type-only 引用（编译期无运行时环）。
- 行为不变证明：smoke 57 组零改动全绿（构造点经适配器兼容）；协议 v2.13 不动；重启恢复/替身生命周期语义逐条保留（review.unit 直测）。

## 后续（B′：一键预设终局，触发信号 Q14-A：复审大改/他人复用/多插件共享域时）

- **双层部署（Q24-A）**：宿主插件 `dsh-pandaclaw` 装服务（域跨会话共享——preset 是会话级组合，ROOT realm 服务被拒，共享服务必须宿主级）；`.agent-presets/` 放三目录——`pandaclaw`（主持人会话：inject 宿主服务 + 装主席台工具面）、`pc-reviewer`（审查替身面）、`pc-supervisor-standin`（监督替身面）；preset 会话层 inject 宿主服务、不重复提供、无 ROOT 冲突。
- **工具工厂导出（Q25-A）**：`leaderFactories/reviewerFactories/supervisorFactories/memberFactories` 已从宿主插件导出（本轮已落），preset cordis.yml 直接引用复用。
- **合包 + 预设 = 终局（Q26-A）**：拆包（core/review 独立插件）留给触发信号。
- **依赖契约（Q18-A）**：PandaClaw 对宿主要求——`agents`（替身 spawn）、`storageDomain`（域）、`tools`/`systemPrompt`/`session`（工具装备）、`sessionProjections`（投影）；对底座 team 要求——产生 Agent 会话 + agent/created 事件 + 子代理作用域工具注册；替换实现须满足上述契约（换 cordis.yml 行 + 换 AgentHost 实现）。
