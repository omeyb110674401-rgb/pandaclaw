## 一、排版参数 YAML 化

**产物**：`.pandaclaw/templates/layout-gbt9704.yaml`（约 230 行）。每个数值行尾注释给出 GB/T 9704—2012 条款号，全部数值溯源 [C-补-P01](./C-补-P01-GB9704原件核对.md)。顶层结构：

| 键 | 内容 | 代表值 |
|---|---|---|
| `meta` | 标准、状态（现行有效）、数值审计指针、单位约定 | mm；96dpi 下 1mm=96/25.4px |
| `page` | 幅面、纸张定量、双面印刷 | 210×297；60–80 g/m² |
| `margins` | 天头 37±1／订口 28±1／右、下白边推算值 | 右 26、下 35（标准未单列，标注推算） |
| `text_area` | 版心 | 156×225 |
| `grid` | 22 行×28 字、「字」「行」定义、双口径行距 | 口径 a≈10.23mm/行；口径 b≈10.58mm |
| `fonts` | 各要素字体字号（基准/标题/版记/份号/密级/紧急/签发人/四层序数/页码） | 三号仿宋≈16pt、二号小标宋≈22pt、四号≈14pt |
| `regions` | 发文机关标志 35mm、发文字号规则、签发人、标题、主送、盖章件/不盖章件编排细则 | 含 7.3.5.2「日期长于署名」兜底 |
| `red_rule` | 发文字号下 4mm、与版心等宽 156mm | 线粗无明文→视觉值声明 |
| `page_number` | 一字线距版心下边缘 7mm、单右双左、免编页码情形（含信函首页）、横排表格 | |
| `version_table` | 粗线 0.35/细线 0.25mm、末条与最后一面版心下边缘重合、抄送/印发编排、W4 双定性 | 最后一面＝硬规则；偶数页＝软提示 |
| `special_formats` | 信函（30mm/170mm/20mm/首页无页码）、命令（20mm/令号）、纪要（35mm/无文号无印章/出席名单编排/开放条款） | |

**设计决策记录（渲染器实现必读）**：

1. **长度单位只用 mm**：CSS 绝对长度直接支持 mm，避免 px 浮点累积误差；px 换算系数仅作备查注释。
2. **pt 对照是出版常识不是标准内容**：GB/T 9704 只规定中文字号名称（二号/三号…），全文无 pt 数值；YAML 注释块已强制声明，防止后续被误引为「国标规定 16pt」。
3. **行距双口径张力**：网格口径（225÷22≈10.23mm）与术语口径（一个汉字高＋3 号字高 7/8≈10.58mm，3.2 条）在标准内同时成立且数值有出入（22×10.58＞225）。处置：正文撑满版心用口径 a，「空二行」等要素间距推算用口径 b，两处均在 YAML 与 demo 中显式声明。
4. **软硬约束分级**：「推荐高度」「推荐红色」等软约束与「必须」「不得」硬约束分开表达；W4 版记偶数页按 P0 定性落为 `placement_hard_rule: last_page_only` ＋ `even_page_convention: soft_hint`。
5. **纪要免章**：`special_formats.minutes.has_seal: false` 注释指向 C-补-P05 的三段式定性，不再重复论证。

## 二、开源字体合规评估

**硬约束（任务原文）**：只评估 OFL 或等效开源授权的仿宋/小标宋替代；**「免费商用但闭源」≠开源授权，一律排除**并单独说明。

### 2.1 合规候选对照表

| 字体 | 承担角色 | 仓库/出处 | 授权 | 风格定位 | 成熟度/覆盖 | 用途建议 |
|---|---|---|---|---|---|---|
| **朱雀仿宋** Zhuque Fangsong | 仿宋替代（正文基准字） | [TrionesType/zhuque](https://github.com/trionestype/zhuque) | SIL OFL 1.1（以仓库 LICENSE 文件为准） | 真仿宋骨架：以宋代刻本与老仿宋为底本数字化，笔形接近传统仿宋 | 活跃开发中（0.x 版本），常用字覆盖可用、生僻字持续补齐【版本数待核】 | **正文链首选**；部署时随分发留存 LICENSE/FONTLOG |
| **思源宋体** Source Han Serif SC（=Noto Serif CJK SC） | 小标宋近似（标题二号字角色） | [adobe-fonts/source-han-serif](https://github.com/adobe-fonts/source-han-serif)、[维基条目](https://zh.m.wikipedia.org/zh-hans/%E6%80%9D%E6%BA%90%E5%AE%8B%E4%BD%93) | SIL OFL 1.1 | 宋体；Heavy/Bold 字重视觉厚度接近小标宋，但**非真小标宋**（小标宋笔形更瘦劲、横竖对比更强） | 极成熟、七字重、GB 级覆盖 | **标题链当前最优合规解**；渲染配 Bold/SemiBold＋微调字距 |
| **霞鹜文楷** LXGW WenKai（GB 版） | 楷体角色：层次序数第二层「（一）」、签发人姓名 | [lxgw/LxgwWenKaiGB-Fusion 等](https://github.com/lxgw/LxgwWenkaiGB-Fusion) | SIL OFL 1.1 | 楷体（Klee One 底本衍生，GB 字面扩展） | 成熟、多字重、社区活跃 | 层次序数与签名姓名字段的开源解 |
| **思源黑体/Noto Sans CJK SC** | 黑体角色：密级、紧急程度、第一层序数「一、」 | Adobe/Google 官方 | SIL OFL 1.1 | 黑体 | 极成熟 | 黑体要素通用解 |
| 不寐仿宋（观察名单） | 备选仿宋 | [100font 项目帖](https://www.100font.com/thread-1838.htm)（自述「以 HZ 宋朝为基底的开源仿宋」） | **待核**——入库前必须人工打开仓库确认 LICENSE 为 OFL 或等效 | 仿宋 | 早期 | 暂不入选型表，仅跟踪 |

### 2.2 排除项及原因（与合规候选同等重要）

| 字体 | 排除原因 |
|---|---|
| 仿宋_GB2312、方正仿宋_GBK、方正小标宋简体 | 现实公文的**事实标准字形**，但属方正电子商业授权字体。「免费商用」（部分方正字体对个人/特定场景）≠ 开源授权：不可再分发、不可内嵌进开源渲染管线、不可随 PandaClaw 打包。demo 仅将其置于 `font-family` 栈首位作为**系统已装时的 fallback**（引用字体名不构成再分发）。 |
| 华文仿宋 STFangsong、华文中宋 STZhongsong | macOS/iWork 随附字体，授权绑定系统，不可独立分发。 |
| 汇文明朝体等社区「免费商用」字体 | 未附 OSI 认可协议，二次分发与内嵌条款不明，按本条目硬约束排除。 |

### 2.3 结论与商用风险点

1. **正文链（仿宋）＝朱雀仿宋（OFL）；标题链（小标宋）＝思源宋体 Heavy/Bold 近似（OFL）**。目前**不存在真「小标宋」笔形的开源字体**——这是开源渲染件与现实红头件之间已知最大的字形差异，模板与产物注释必须声明「本 PDF 为开源字体渲染件，字形与正式印制件存在风格差异」，避免被当作正式制式文书外传。
2. **部署合规动作**：①各字体 LICENSE 文本随分发目录留存；②不得在产品文案中以「方正」「思源」等商标名暗示官方背书；③保留 FONTLOG/版本信息满足 OFL 3.x 条款。
3. **fallback 策略**：`font-family` 栈＝开源首选→系统商业字体名兜底（demo 已实现），保证在装有商业字体的终端输出更接近正式版的预览，而分发包本身只携带 OFL 字体文件。
4. **待核项**：朱雀仿宋当前版本号与覆盖率具体数字、不寐仿宋授权协议——本轮检索无法读取仓库文件全文，落地前人工确认一次即可关闭。

## 三、HTML print CSS 原型（红线＋印章下压＋骑缝可行性验证）

**产物**：[`C-补-P15-红头版式demo.html`](./C-补-P15-红头版式demo.html)——自包含单文件（约 26KB，**零外部请求**，不引入任何字体文件与网络资源），屏幕预览与 `@media print` 输出双态。

### 3.1 四个板块

| 板块 | 演示内容 | 关键实现 |
|---|---|---|
| ① 标准红头首页 | 份号/密级「秘密★1年」/特急占位（7.2.1–7.2.3）；发文机关标志距版心上边缘 35mm 红色（7.2.4）；发文字号「爪委发〔2026〕5 号」六角括号＋不补零（7.2.5）；红线位于字号下 4mm、与版心等宽（7.2.7）；二号标题空二行、主送空一行、正文 22 行网格＋段缩进二字（7.3.1–7.3.3）；署名居中于成文日期之上、日期右空四字（7.3.5.1）；印章 Ø45mm 下压 | CSS 变量驱动，每个声明行尾注释条款号 |
| ② 末页·版记＋页码 | 主送移版记改「主送」（7.4.2）；抄送句号；印发机关左空一字/印发日期右空一字加「印发」（7.4.3）；粗 0.35mm/细 0.25mm 分隔线、末条与版心下边缘重合（7.4.1）；页码一字线距版心下边缘 7mm、单页右空一字/双页左空一字（7.5） | 版记 `margin-top:auto` 沉底即「末条重合」的实现 |
| ③ 骑缝章示意 | 同一 `<use>` 引用的两份印章拷贝，尺寸 42mm、纵坐标一致，`clip-path: inset()` 各取一半，分别锚定相邻两页拼缝两侧 | 真实跨页＝每页页脚层绝对定位同几何半章，参数不变 |
| ④ 信函格式变体 | 标志不带「文件」、距上页边 30mm（10.1）；170mm 红双线：上线标志下 4mm 上粗下细、下线距下页边 20mm 上细下粗；发文字号顶格居版心右缘、距双线 3 号字高 7/8≈4.9mm；首页不编页码注记 | 双线以负外边距越出内容盒实现「170mm＞156mm 版心」 |

### 3.2 印章下压位置算法（7.3.5.1 文字规则的代码化）

```
规则一  印章端正居中下压署名与成文日期，使二者处于「印章中心偏下」
        → sealCenterY = signBlockTop + blockHeight × 0.45
规则二  印章顶端上距正文（或附件说明）「一行之内」
        → clamp(sealTop, bodyBottom, bodyBottom + 10.58mm)
规则三  水平对准署名轴（单一机关场景署名居中，印章随之居中）
        → centerX = orgSign 水平中点
```

页面顶部实时读数面板输出毫米换算值供逐条对照标准。**修复后实测读数**：`章顶距正文 0.0mm（≤一行 10.58mm ✓）｜章心较署名日期块中心偏上 0.3mm（二者处中心偏下 ✓）`。

### 3.3 验证结果（机器度量）

- 三张纸张容器（首页/末页/信函页）`scrollHeight − clientHeight` **全部 = 0**（修复前首页 +23px，见 §六）；
- `@page { size: A4; margin: 37mm 26mm 35mm 28mm }` 已内置，浏览器「打印→另存为 PDF」即为管线级验证路径；
- 截图留档：`C-补-P15-红头首页验证.png`（辅助线模式可切换核对天头/订口/版心虚线框）。

### 3.4 已知限制（诚实清单）

1. 印章为 CSS/SVG 演示图元，**非电子签章**——效力层面衔接 C-补-P03 电子印章体系，不在本 demo 范围；
2. 骑缝章为一页内模拟，真实分页场景需按 3.1 板块③注释迁移；
3. 视觉值三项已在 YAML 声明为非标准内容：红线粗 0.7mm、标志字号 34pt、红色 #d0021b；
4. 屏幕预览用固定 210×297 盒模型，打印时退化为普通分页块——两种形态的坐标原点差（天头偏移）已在 `@media print` 内补偿。

## 四、对渲染管线的选型结论

1. **参数单一来源**：渲染器只读 `layout-gbt9704.yaml`，禁止在组件里散落魔法数值（AGENTS.md「no hardcoded tunables」约束在本模块的落法）；
2. **字体方案**：正文朱雀仿宋／标题思源宋体 Heavy／楷体霞鹜文楷／黑体 Noto Sans——**全部 OFL**，可随管线合法分发；系统商业字体仅作运行时 fallback 名；
3. **打印路线**：纯 print CSS（@page＋绝对定位）已被 demo 证明足以承载红线、印章下压、版记沉底三大难点，**无需引入额外排版引擎**；PDF 导出走浏览器打印或 headless Chromium 均可；
4. **遗留风险**：①小标宋无真开源字形（§2.3 已声明）；②朱雀仿宋生僻字覆盖仍在增长，涉罕见人名地名时需 fallback 兜底；③跨平台默认字体会造成预览差异，交付物应以 PDF 为准而非屏显。

## 六、工具坑记录

1. **子代理两次中断于像素级精调循环**：P1-5 子代理完成 YAML 与 demo 主体后，在「首页末段折行导致 23px 溢出」的迭代中耗尽上下文失败。主会话接管：定位溢出根因（首段 40 字按 28 字/行折两行，叠加 `text-indent:2em` 后实际行容量 26 字），将首段精简为 22 字单行，复测三张纸溢出全部归零。
