# D 线（四类文件流程）· 后续补充调研方案

> **定位**：`D-四类文件.md` 已完成四类现实文件的骨架流程调研；一次调研不可能穷尽细节，本方案盘点当前证据强度、列出未尽对象、按优先级给出可领取的调研问题清单，供后续轮次逐条执行。
> **对应系统版本**：PandaClaw v2.1 会议矩阵（纪要 MIN / 决议 RES / 协商 CON / 规划 PLA / 战略 STR / 立法 LEG）。D 线四类文件的映射：白皮书 → **协商型 CON**；中央一号文件 → **战略型 STR**；五年规划纲要 → **规划型 PLA**；行政法规 → **立法型 LEG**。
> **证据等级约定**（沿用至后续所有调研产物）：
> - **A**＝制度性原文（法律法规条例全文、宪法、议事规则等），可直接作为机制依据；
> - **B**＝权威综述或多源交叉（官方媒体综述、学术专著＋官方转载互证）；
> - **C**＝个案报道或单源推断（单一媒体报道、凭既有知识写就待复核），只能作参考，不得单独作为机制出处。

---

## 〇、使用说明

1. 每个调研问题独立成轮，产出写入同目录 `D-补-<编号>-<主题>.md`（编号取问题编号，如 `D-补-P03-政府工作报告.md`）。
2. 方法论沿用本轮：web_search 定位 → 权威全文抓取 → 双源以上交叉 → 逐事实标注来源 URL 与证据等级。
3. **已知工具坑**：本轮浏览器直连部分站点出现内容错位（北方网 enorth、中新网 chinanews、国新办 scio.gov.cn、中国政府网 gov.cn 部分内页返回无关页面）。后续对 gov.cn/scio 内页建议改用 anysearch 的 URL 内容提取、政府网站内检索接口或权威镜像站，抓取后先做内容一致性抽查再采信。

### 1.3 方法论教训（供后续各调研线复用）

1. 浏览器抓取存在内容错位风险（详见〇-3），凡关键事实必须双源以上且至少一源为成功核对的原文。
2. 检索词组合策略有效样例："`<文件名> 出台过程/诞生内幕/起草始末`""`<年份> 中央农村工作会议 讨论稿`"——个案报道常比制度文本更能还原程序细节。
3. 法规类事实优先找中国政府网 `zhengce/content` 页面的全文页（带发文字号与修订沿革），一次抓取可覆盖多个问题。
