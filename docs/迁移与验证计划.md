> 前置状态：协议校准完成后再执行本计划。安装本身随时可做，但实战演练必须等协议 v2.1 定稿。

## 1. 安装步骤（已核实的机制）

`dsh plugin --profile <name> <args...>` 是 pnpm 转发器：在 profile 目录执行 pnpm，然后把「声明了 `dsh.bundle` 的依赖」自动追加进 bundle 层叠。因此：

```sh
# 1) 安装（npm 预构建包，当前版本 0.2.7）
dsh plugin --profile web add dsh-team

# 2) 确认装配：bundle 层应出现 dsh-team
dsh --profile web --dump-config | grep -B2 -A8 'team'
```

## 2. enterprise 档配置覆写

dsh-team 默认 `maxTeammates: 8`，enterprise 档需要 5+5=10 名成员。用户补丁层在 `C:\Users\35258\.dsh\profiles\web\cordis.patch.yml`（当前为空数组），追加：

```yaml
- id: <dump-config 里看到的 team 行 id>
  config:
    maxTeammates: 12
```

写完后用 `--dump-config` 复核合并结果。注意 undo-savepoint 会自动给这次配置变更拍快照，改错可回退。

## 3. 重启与工具验证

1. 重启 DSH（web profile）。
2. 新会话确认 `team_spawn / team_send / team_task / team_note / team_board / team_list / team_relation / team_dismiss` 八件套出现。
3. 确认 `pandaclaw-meeting` 技能已采纳生效（技能目录可见）。

## 4. 实战演练设计（协议验收）

| 场次 | 类型 | 目的 | 规模 |
|---|---|---|---|
| 演练一 | MINUTES | 最小闭环：建会→记录→轻量确认→存档，验证回合驱动屏障与板书 key 规范 | simple (2+1) |
| 演练二 | CONSULTATION | 完整回路 R0-R4：独立陈述屏障、质询转发、机械计票、打回重议、KEY 验收门暂停 | medium (3+2) |

每场检查点：
- [ ] 成员全程 managed，无横向消息（team_list 的 mailbox 流量里 from/to 只允许 →leader）
- [ ] 板书 key 符合 `opinion-* / inquiry-* / reply-* / vote-* / resolution-*` 规范
- [ ] 计票只统计 vote-* 记录；打回时反对理由被正确提炼为质询焦点
- [ ] 验收门真的停住等用户输入
- [ ] 最终文档字段全部可溯源到 board key
- [ ] token 消耗记录（评估意见书≤300字等上限是否有效控费）

## 5. 回滚

```sh
dsh plugin --profile web remove dsh-team   # 移除插件
```

undo-savepoint 快照兜底配置层回退。队友 transcript 在插件移除后仍留在 harness 子代理目录（dsh-team 已知限制，无害）。
